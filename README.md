# Medic.ai — AI Medical Record Assistant Indonesia

Medic.ai is an AI-assisted medical documentation service for Indonesian healthcare workers. It converts explicitly stated patient information from chat into structured records, validates the data, shows a preview, waits for explicit confirmation, then stores the record in Google Sheets and optionally indexes a read-only visit summary in Chroma.

## End-to-end flow

`WhatsApp / REST → Extractor → Validator → Preview → YA → Medical Record ID → Google Sheets → Chroma history`

### Safety boundaries

- No hallucination: missing clinical facts remain missing.
- Patient history is read-only context and never auto-fills a new visit.
- No record is written without explicit `YA/YES` confirmation.
- Medical Record ID is generated by deterministic code, not the LLM.
- Existing non-empty A-L Sheets schema is never silently replaced.
- WhatsApp senders can be restricted with `AUTHORIZED_PHONE_NUMBERS`.
- Meta `X-Hub-Signature-256` is verified when `WHATSAPP_APP_SECRET` is configured.
- Medic.ai is not a diagnostic, prescribing, or clinical decision-making system.

## Repository structure

- `main.py` — production-oriented FastAPI entrypoint and orchestration.
- `agents/` — extractor prompt, validator and writer safety boundary.
- `memory/` — Chroma patient-history storage and embeddings.
- `tools/` — deterministic Medical Record ID generator.
- `whatsapp_webhook/` — standalone WhatsApp gateway compatibility package.
- `tests/` — validation, ID and confirmation-boundary tests.
- `docs/DEPLOYMENT.md` — deployment, Google Sheets and WhatsApp configuration.

## Quick start

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env
uvicorn main:app --reload --port 8000
```

API endpoints:
- `GET /health`
- `POST /chat`
- `GET /webhook/whatsapp`
- `POST /webhook/whatsapp`
- `GET /records`

Run tests:

```bash
pytest -q
```

For production setup, read `docs/DEPLOYMENT.md`, `docs/ARCHITECTURE.md`, and `docs/SECURITY.md` before connecting real patient data.
